## 實際斷點與修正

| 斷點 | 修正及邊界 |
| --- | --- |
| 模型只能使用先前少量研究結果，無法指定補查另一檔股票。 | `autonomy.research(symbols=[...], deep_limit=...)` 產生新的持久研究版本；省略標的仍使用覆蓋輪替。指定清單須為 1–20 個不重複的正規台股代碼、不得超過 `deep_limit`，且符合 Host 指定的股票範圍。與 `cycle_id` 回讀互斥，格式與範圍先於服務初始化檢查。 |
| 缺少批次報價的已知股票無法進入補歷史路徑。 | 指定研究由完整掃描名單核對身分與現有商品排除旗標，不要求先有當日批次收盤價。未知、重複或跨市場身分衝突的批次在歷史下載前拒絕；提案及送單仍執行原有獨立檢查。 |
| 一個固定策略評估失敗，會丟失已保存合格歷史在研究結果中的索引。 | 歷史完成來源、股票身分、至少 62 根、時間順序、非未來資料及雜湊檢查後即進入 `results`。訊號、評估與資格收據保存失敗分開記錄；只有完整成功的候選才含資格 ID。模型仍可用已核實歷史提出自己的假說，失敗的固定候選不能建立固定策略計畫。 |
| 評估故障被當成歷史失敗，反覆占用下載重試額度。 | 歷史覆蓋成功以保留的核實歷史計數；候選評估成功／失敗另列。`deep_success_count_scope=verified_history_retained` 不表示策略有效，也不回寫舊循環。 |
| 快取命中後同步 CPU 評估占用事件迴圈；取消下載仍可能繼續請求月份。 | 固定候選的純計算移至 worker，保存仍由呼叫端完成。取消後不再啟動下一候選或股票，不保存取消後的資格／循環。官方 loader 接收 Host 停止事件，停止後續月份、限流後請求及轉址重試；已在途 I/O 保留原逾時設定，已收到原文照常核驗保存。 |
| 同一模型任務由原循環 A 補查 B，會把 A 的觀察內容混入凍結提示政策。 | 以該任務的原始 Host 中繼資料找到帳戶所屬、雜湊正確的 A，精確比對原生成提示及 API 正規化版本；凍結提示保持一致，證據綁定實際 B。自訂提示、錯誤帳戶、缺失／損壞來源不能利用模板剝除。 |

全市場掃描證據與累計「標的 × 策略版本」研究分母保留，指定一檔不把分母改成一檔；指定研究也不推進原輪替游標。模型使用新循環提案及啟用，仍沿用同一 run；每日預算依不同 run ID 計數，不因 A、B 兩個循環加開任務。

模型投影分開呈現核實歷史及候選故障，保留指定股票、可回查歷史／資格 ID、錯誤階段與省略筆數。原 6,000 字元結果上限、600 秒工具上限、20 檔、50 個月份、三次新來源失敗停止及 0.25 秒來源限流均未提高。授權、資金、風控、成本與 M7 資格條件未放寬。
