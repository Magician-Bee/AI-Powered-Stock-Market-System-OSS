# 自主交易流水線

最終產品目標是由系統自行研究市場、形成可驗證策略、選擇部位及進出場時機，經共用交易計畫、風控與券商介面執行。目前接本地 Paper Broker；真實券商尚未啟用。紙上成交與正期望值資格各有自己的證據，不能互相代替。

## 從研究到持倉

1. `BroadScanner` 批次讀取上市櫃證券名單、官方報價及已連接因子，保存整個市場的覆蓋數與資料日期。
2. `AutonomousCampaign.research` 在每輪預算內輪替深入檢查股票，從交易所核對代碼、月份、原始回應及 hash 後取得約四年日 K。預設每輪 20 檔；系統按帳戶永久保存每檔上次嘗試、成功次數與錯誤，優先從未查或最久未查者，避免每日成交排名改變造成漏查。月資料逐檔快取，研究覆蓋數與全市場掃描數分開呈現。
3. 固定策略族群先凍結規則，再以依時間排序的訓練、驗證、保留區間計算淨交易收益；模型自評信心不作為正期望值憑證。
4. Codex 可在同一研究任務呼叫 K 線、基本面、籌碼與事件工具，以 `autonomy.propose_plan` 提出自己的部位與交易條件；資料缺項會保留，不把工具存在視為已全面取證。固定 K 線假說供比較，不限制模型只能選這兩種；每份模型計畫保存實際模型、推理強度、原始決策與 Host 留存證據。
5. `TradingPlan` 保存股票、策略版本、證據、股數、資金上限、開始時間、觸發價格、有效期、停損、目標與持倉截止時間。
6. `TradingPlanExecutor` 在條件到達時重新核對報價、帳戶、成本、掛單預占與中央風控。先保存送單意圖，再取得券商回報；未確認回報先對帳，不猜測重送。
7. 之後持續管理部分成交、撤單、出場及剩餘股數。計畫、事件與帳本保存在 SQLite，UI 關閉不會遺失。服務重啟後依原委託識別碼接續。已驗證從 SQLite 重建元件；OS 行程故障注入與跨日運行另待實測。

`autonomy.status` 與狀態 API 直接讀取隔離自主帳戶，回傳現金、淨值、持倉與掛單預占。模型摘要會標明省略的筆數，保留每日複查額度；查詢時間不代表行情已更新。恢復既有任務時，網路研究不能取代保留的自主研究 cycle，暫時性研究失敗最多重試一次。

狀態內的 `paper_decision_context` 分別列出建立計畫所需條件、實際送單條件與績效資格。每計畫 5% 是含成本保留的資金配置上限，停損損失另以價差、股數和成本核對中央限制；受資金上限縮小後，顯示實際配置並保存模型原始要求。現價 100、突破 110 進場、停損 105 的計畫會等待 110；回檔計畫也先等觸發。觸發時若已跳過止損／目標區間仍會拒絕進場，持倉後的保護不受影響。

一般 advisory 排程保持原權限；自主紙上交易使用自己的持久 campaign。等待價格、時間和定期對帳不需要反覆呼叫模型。 全市場研究使用專屬唯讀工作設定，工具宣告的 600 秒期限會保存為實際執行上限；可以取消，且不擴大交易與其他一般工具的期限。

macOS `.command` 的 Uvicorn 服務由專案專屬 launchd keepalive 工作持有。行程意外退出會由 launchd 重生；每次啟動都在 `exec` 前原子更新專案 PID 檔，因此版本驗證、停止與再次開啟會指向真正的新行程，不會因故障前的舊 PID 誤判服務狀態。

啟用後依交易日收盤排程嘗試批次研究，成功後集中交給既有 Codex Agent Runtime 複查，保存成功、失敗與預算紀錄。預設每日最多一個模型任務、每個研究週期最多一次；當前已執行的原生 Agent 任務也計入預算；同一 run 複查多個 cycle 只計一次，未知提交按獨立提交鍵計算。模型與推理強度取自啟用任務的實際設定並保存，之後 UI 切換其他模型不會偷偷改動既有自動交易的設定。回報不確定時先找既有 run，不重新付費發一個。跨交易日長期運行仍需累積實際紀錄。

模型能用 `autonomy.close_plan` 重新評估並取消未進場計畫，或對計畫所擁有的已成交股數請求出場。固定規則持倉另在每個新收盤 K 線檢查同版本策略是否失效。價格停損、持有期限與委託對帳由程式持續管理。停用新進場後，既有委託與持倉仍會接續核對。顯式停用會記錄時間，早於這次停用的舊任務不能重新啟動；使用者之後的新啟用指示可重新授權。停用不需要先通過研究週期檢查。

## 未成交出場與行情中斷

出場單等待超過 60 秒且仍未成交時，未設定替換政策的舊計畫會保存 `exit_alert`、實際剩餘股數與原單識別；告警不代表已退出。停損已觸發而進場撤單尚未確認時，退出原因會先持久化，重啟或價格反彈不會抹掉退出要求。

新模型提案可明示 `exit_order_policy={"wait_seconds":60,"max_replacements":2,"minimum_limit_price":90}`。這是契約示例：最低賣價必須不高於該計畫停損，中央風控在買進前會依較低的退出底價計算損失預算；原停損觸發價保持不變。出場等待超時後，必須先確認原單撤銷或終止，再依真實剩餘股數有界重掛；價位低於底價或替換額度耗盡會升級告警，不宣稱已經退出。每筆替換仍須通過當前報價、交易單位、券商能力與成本核對。

撤單傳送的次數與重掛額度分開：同一張仍開啟的委託最多傳送三次撤單，每次至少間隔政策指定的等待秒數，傳送前先保存次數及時間。未取得終止確認不新增賣單。台股退出底價向上取合法價格跳動單位；若取整後超過停損則拒絕計畫，原始政策與停損均保留。券商預檢拒絕出場時，保存實際阻擋碼與剩餘股數；舊計畫跨日後原限價不在當日合法價域，也會明確告警。

持倉管理優先核對已有委託，之後才處理新進場。單一行情讀取最多等待 10 秒；逾時會保留來源錯誤，繼續可執行的對帳及撤單流程，不能拿空行情撮合成交。每次取得行情後更新執行時計，避免前一檔網路延遲造成後一檔新行情被誤認為未來資料。

## 操作入口

Agent 先以 `autonomy.research` 取得 `cycle_id`，用 `autonomy.evidence` 讀取已保存的 K 線與驗證內容，再整合其他市場工具形成判斷。`autonomy.propose_plan` 保存模型選定的股數／資金比例、指定時間、觸發價、停損、目標和期限；`autonomy.activate` 啟動管理。沒有足夠進場條件可以保留現金、啟用後續研究。只有明確指定 `use_candidate_plans=true` 才採用固定 K 線候選計畫。

比較一輪 20 檔時，`autonomy.evidence(evidence_ids=[...], view="summary")` 在一個工具呼叫內回傳逐檔 OHLCV、5／20／60 日報酬、SMA20／60、RSI14、ATR14、量比及來源核對；模型只對決賽候選再讀原始 K 線。這避免逐檔把數百根 K 線反覆塞回模型 context。Host 將自主研究與保留歷史視為本流水線的正式行情／技術證據，再依使用者要求引導模型補月營收、外部研究與個股風險，不會因工具名稱不是舊 `market.*` 而誤擋。

啟動及變更需 `paper_execute`，並由 Host 根據使用者任務確認自主交易範圍；單筆模擬買一股不會授權全市場持續交易。自主任務可以使用市場、網頁研究與風控工具，避免誤套單筆委託的狹窄工具清單。 詢問流程的說明、設計或評估不會自動取得交易權限。目前持久 campaign 管理整個自主帳戶，需全市場授權；僅指定單一股票的任務可研究、保存該股票計畫與管理已有風險，不能藉 `activate` 擴大成全帳戶持續交易。

全市場範圍由 Host 保存，畫面選中的股票、研究編號與每日複查中的候選代碼都不會自行縮小授權。單純補充事實會寫入原任務，保留原目標；暫停中的任務仍維持暫停。若要在修復後接續同一任務，可使用既有 `/api/agents/runs/{run_id}/replan` 控制入口。只有確認啟用在範圍檢查時、任何服務寫入前被拒絕，才允許原參數一次重試；不確定的寫入結果仍須先對帳。部分完成的任務可在原 run 續接；成功變更後的狀態查詢會取得新的帳戶收據，避免沿用變更前的快取。

Host 接受模型將計畫更新欄位放在 `changes` 或支援的外層格式，仍保留不可改寫的執行紀錄。使用者已交由 Agent 決定的欄位清單不會再被誤轉成二選一；「未來條件成立才通過正期望值資格」也不會被當成現在已獲利的宣稱。

提案可引用同一任務已成功讀取的工具呼叫編號。Host 核對任務、帳戶、安全 checkpoint、工具成功收據與結果雜湊，再轉成穩定的保留證據編號；模型不能自行提供證據內容或借用其他任務。若舊版本確實在建立計畫前因證據編號無法解析而拒絕，修復後允許原參數一次重試，原失敗與新收據並存。成本、Token 或執行上限耗盡後停止自動續跑，明確繼續操作另留授權紀錄。

API 共用既有本機 session 保護：

| 方法與路徑 | 用途 |
| --- | --- |
| `GET /agent/autonomy/status` | 帳戶、啟用狀態、研究與交易計畫 |
| `POST /agent/autonomy/research` | 批次掃描全部市場，預設輪替深查 20 檔；`deep_limit` 可控制單次深查數量 |
| `GET /agent/autonomy/cycles/{cycle_id}` | 讀取已保存的研究證據 |
| `POST /agent/autonomy/activate` | 啟用紙上管理並請 Codex 複查指定研究週期 |
| `POST /agent/autonomy/control` | 設定 `enabled` |
| `POST /agent/autonomy/manage` | 立即進行一輪對帳與條件檢查 |

使用獨立 `autonomous-paper-v1` 帳戶，初始模擬資金 100 萬元。既有手動模擬帳戶不會被重設。委託上限 5%、總實驗曝險上限 20%，再受中央帳戶風控限制；此預算是收集紙上證據的設定，不是已驗證的最佳投資配置。

## 成本與證據

新紙上帳戶明確設定手續費 14.25 bps、每筆最低 20 元、股票賣出稅 30 bps、滑價 5 bps。這些是模擬假設，不表示已取得使用者券商折扣或成交品質。最低手續費依同一委託累積成交補差額，不對每個部分成交重複收取。

目前免費 MIS 來源提供整股成交資料。新的自主帳戶可用明示的零股代理撮合：原始成交必須有效且即時，每個來源時段只使用其量的 1%，最多 25 股，並加 20 bps 不利價格衝擊。原限價與交易時段仍須成立，否則等待；這些成交標記為模擬，不能當作真實零股成交品質或券商執行證據。其他帳戶原有嚴格零股撮合設定不變。

自主帳戶的整張交易另採 `BoardLotTradeModel`：連續盤內每個可核對來源成交事件使用其量的 1%，向下取整張，預設最多 1,000 股，並加至少 20 bps 不利衝擊及原滑價。來源量不足、未知、限價不符或已跨入收盤集合競價就等待。來源容量按帳戶與成交事件保存，跨委託及重啟不會重複使用；這是保守的模擬情境，尚非實證成交機率。

股票一般賣出證交稅為 0.3%；券商手續費由券商訂定，實際產品與日沖條件應使用相應成本表。[臺灣證券交易所投資指南](https://www.twse.com.tw/zh/about/company/guide.html)。ETF 的一般賣出稅率為 0.1%，債券 ETF 另有暫免期限，不能把普通股票成本套給所有產品。[ETF 交易規則](https://www.twse.com.tw/zh/products/securities/etf/overview/rules.html)。初版自主候選族群限普通股票，其他產品保留在證券覆蓋統計中。

報價 `received_at` 只記錄取得時間，新接收到的舊成交不會變成新成交。研究、估值與撮合分別判斷，不能因為報價目前不適合送單便連歷史研究都阻擋。

官方 K 線也分開判斷來源核對與月份覆蓋。缺少部分月份時，已核對且至少 62 根、時間順序正確的資料可保留供 Agent 自訂紙上計畫使用；完整區間的固定策略回測仍會顯示覆蓋不足。股票身分不符、雜湊損壞或非官方來源仍拒絕，並保留每月嘗試的診斷收據。

自主深查現在請求 49 個月份、約 1,000 根完成日 K，讓固定 70/15/15 分割的 validation 與 holdout 各能超過 120 根。2026-09-12 實際以台積電測量：既有 12 個月快取、37 個官方月份網路補齊，共 977 根、缺月 0、耗時 4.4 秒。這是來源與效能探針，尚未處理公司行動、歷史資料首次可得時間或券商實證成本，因此本身不會取得正期望值資格。

交易所歷史回補會辨識 TPEx 不同年代的明示單位欄位：成交張數／成交仟股以一千股換算，成交股數以一股換算；成交仟元與成交金額（元）也分別換算。未標單位仍拒絕。真實網路請求全域限制為每 0.25 秒啟動一筆，降低 TWSE CDN 在大量月份回補時回傳同址 307／308 的機率。只要正式帳戶要求四年區間，當日最新但只含舊一年範圍的保留快取會先升級；已明確請求四年而因新上市僅有較少 K 棒的資料則不會無限重抓。

先前深查失敗的股票不必等完整輪替才再試。每輪最多四分之一名額依失敗時間重試，其餘至少四分之三繼續覆蓋從未深查或最久未深查股票；重試成功會清除錯誤，持續失敗也不能占滿整輪。

上市與上櫃的官方探索來源彼此獨立。單一交易所暫時傳輸失敗時，已成功核對的另一交易所結果仍可用，但不能被表述為完整市場覆蓋；後續全市場研究繼續保存各來源的成功、缺口與錯誤。

## 正期望值資格

`bounded_experiment` 表示可以在明確紙上風險預算內收集證據；`qualified` 另需核對策略版本、原始資料、公司行動、歷史可得時間、實證成本、時間切分及淨期望信賴界線。單檔、少量成交或整體多重測試未處理的結果，都不能稱為已證明全市場有正期望值。

模型不必等到正期望值已獲證明才提出小額紙上試驗。其他策略引擎的研究資格不足，不直接等於自主帳戶拒絕這份計畫；實際提案與送單仍各自核對來源、授權、資金、風險、成本和可執行行情。這項區分不代表必須進場，也不能把試驗權限當成獲利資格。

目前先建立兩個固定 K 線研究假說：20／60 日趨勢突破與趨勢回檔再站回均線，使用 ATR 停損／目標。它們是可比較的初始候選，不代表已驗證賺錢，也不是整個 Agent 最終只能使用的策略。基本面、事件、跨市場及其他模型策略需沿用相同證據與交易介面逐步納入。

已平倉計畫會按其實際送單記錄綁定買賣成交，核對股數、費稅與淨現金流後保存成果。其他部位的漲跌不能算進這筆策略收益。這些成果是後續學習的觀察資料；累積模擬獲利不會自動把資格改成「已證明正期望值」。

`AgentForwardValidation` 提供獨立的前瞻紙上政策資格。Host 在觀察行情發生前凍結實際模型／推理強度、提示、工具、執行程式、資金規則、股票池及成本；不同交易計畫保留自己的定義 hash，同一政策可累積多筆結果。自動複查的固定指令與每天的市場資料分開，人工臨時目標保留自己的版本。改動政策會留下偏離或終止紀錄，已花費的多重試驗額度不會重設。

登記股票池沿用計畫建立器支援的普通股票代碼，排除清單及原因另有帳戶證據收據。尚未成功登記的失敗嘗試可在輸入修復後重新準備，原失敗仍保留；已登記的方案不能藉此改寫版本、回填提案或重新挑選較有利的觀察期。

目前方案事前指定至少 120 個每日觀察及 30 筆平倉、14:35 臺北時間記錄淨值、固定期末評估，以零收益現金作比較。已登記計畫會保留進場時間下限與期末觀察前的退出期限。每日淨值必須核對實際帳戶及當日行情；漏掉的觀察不能事後用歷史行情補成前瞻資料。成交與費稅來自本帳戶的 Paper OMS，人工模型報酬或其他帳戶的獲利不算。

評估使用每日投資組合淨收益的區塊抽樣信賴界線，並對同一資料庫內的多次前瞻試驗分配統計顯著水準。通過仍只代表該凍結紙上政策在登記股票池與成本情境下的證據；不代表真實券商成交品質、保證未來獲利或勝過市場指數。模擬測試資料明確排除，不能取得真市場資格。這條路徑不會因資格尚未成立而阻擋已授權且符合風控的紙上計畫。

前瞻期間若模型、工具、執行程式、風控或成本政策改變，Host 先保存不可變偏離收據。帳戶已平倉時立即把舊方案封存為未通過，等待下一個模型複查在報酬發生前登記新方案；仍有持倉時繼續保護、退出與成果對帳，但停止替已失效方案新增每日觀察，平倉後再封存。狀態會顯示偏離數與 `qualification_continuity_intact`，不再把已失效方案只顯示成一般收集中。

跨年度日曆、公司行動、資料覆蓋及長期服務中斷仍需持續核對。若固定觀察缺少必要資料，會保留原因而不自動通過；不能把當日接收到的昨日收盤價當成當日估值。

## 合併驗證

計畫生命週期、回應遺失、部分成交、停用、掛單預占、手續費、排程去重及資料身分檢查使用離線整合測試；雲端模型集中使用整合目標驗收。實機過程若揭露 Host 缺陷，修復與重試照實保留，不計為一次無重試成功。離線測試的假行情會明示為 fixture，不寫入真市場獲利證據；模型實際提案、成交與平倉閉環另依原生執行收據驗收。

單一工程閉環可用以下命令在全新的隔離 SQLite 執行。它會實際經過研究、建立計畫、Paper Broker 買進、持倉管理、賣出、平倉對帳、扣成本淨損益及成果帳本，並核對重複對帳不會新增成交。行情明確標記為 fixture，因此只證明正式程式路徑可達，不是獲利證據。

```bash
uv run python scripts/verify_autonomous_closed_loop.py \
  --database output/closed-loop-acceptance.sqlite \
  --output output/closed-loop-acceptance.json
```

已保存的真實研究循環可用只讀審核器重算內容身分、時間順序、train／validation／holdout 邊界、成本欄位、帳本一致性及資格原因：

```bash
uv run python scripts/audit_autonomous_oos.py \
  --database /path/to/open_stock_ai.sqlite \
  --cycle-id AC-... \
  --output output/oos-cycle-audit.json
```

審核器只做描述性彙總；不同股票各自的一百萬元重播帳本不能相加冒充共用現金投資組合，也不得依 holdout 贏家反向挑選前瞻政策。
