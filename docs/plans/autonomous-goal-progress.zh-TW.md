## 使用既有帳本審核

先以 `verify-stock-ai-instance.sh` 與基準報告確認目前服務的實際路徑；不要在工作區直接採用另一份 `output/open_stock_ai.sqlite`。

```bash
PYTHONPATH=src .venv/bin/python scripts/audit_autonomous_lifecycle.py \
  --database '<正式服務的交易 SQLite 絕對路徑>' \
  --runtime-database '<正式 Agent SQLite 絕對路徑>' \
  --account-id autonomous-paper-v1 \
  --output '<新的審核 JSON 路徑>'
```

審核器的成功退出碼只表示完成讀取及審核，不等於 M1 通過。模型名稱、工具 completed、委託、成交、退出、結果及版本必須分別核對；舊版資料、來源不明或缺收據皆留明確缺項。

## 第八輪：官方名錄身分正式導入與研究可見性

以同一個 `security_master` Incremental Loader 與既有生命週期 writer 回讀三個新鮮、雜湊通過的官方 ISIN 原文。名錄只提供身分、類型與掛牌日：未被公司／ETF／權證清冊採用前維持 `unknown` 或 `pre_listing`、`quote_present=false`，不補造 issuer、到期日或 active。正式 UI 同步使市場庫由 55,985 增至 58,056 個實體，新增 6,213 個 `twse_isin` 識別碼；0 merge。新增 2,071 筆精確分布為權證 2,061、普通股 5、ETF 1、其他證券 4，以及 unknown 1,320、pre-listing 751。

38 組未來權證以 venue＋ISIN 建立新 ID，舊到期實體、76 個舊識別碼及 38 筆不可變 revision 經唯讀逐列雜湊核對未變。後續官方清冊可在發行證據完全一致時採用名錄實體並補生命週期；代號／名稱近似不足以合併。現行精確 ISIN owner 會優先於沒有 ISIN 的歷史同碼列，仍有多個精確 owner 或不可變識別區間衝突時 fail closed。

市場特徵層把 unknown、pre-listing、listed-pending-quote 與 suspended 列保留在研究輸出，原始缺值與原因照實呈現；非 active、來源不符或同碼歧義不得借用其他實體行情或進場因子。全量本機讀取上限提高至 100,000，仍不代表每一檔都有價格、財務、籌碼、事件與交易成本。App 的「證券主檔」頁新增明確同步按鈕，空白搜尋只顯示等待輸入；搜尋結果顯示生命週期，只有 active 身分可開啟圖表，其他列明示僅供研究。

原生 App 搜尋 `00838B` 顯示生命週期待核驗與 disabled「僅供研究」；`085974` 同時顯示預上市新發行與已到期舊發行，兩者均不可開圖。後驗唯讀稽核在 2,071 筆新實體、識別碼、revision、事件、38 筆舊權證與自主帳戶皆為零差異，完整回歸 **566 passed、0 failed**。本輪沒有呼叫新模型、建立計畫或下單；`autonomous-paper-v1` 仍為 TWD 1,000,000，計畫、委託、成交、持倉與成果均為 0。M1 真模型自然提案、進出場與對帳仍未驗收；M7 的 120 日／30 筆、M8 的明示實盤授權及 M9 其他市場也維持未通過。正式資料、UI、回歸及發布收據見 [名錄身分與研究範圍報告](../audits/catalogue-identity-research-ingest-20260913.md)。

## 第九輪：逐檔、多領域研究覆蓋帳本

原本 `autonomous_deep_research_coverage` 只保存被選中代號的曾經成功／失敗次數，無法回答完整市場中哪些 entity 從未深入、舊證據是否仍有效、每個資料領域缺什麼，也可能讓重用代號借到舊發行歷史。新帳本以 account＋不可變 entity 為主鍵；當來源對同一代號回傳多個發行身分時逐一展開並標示 conflict，symbol-only 舊紀錄維持 `not_attributed`。

每次既有全市場研究保存 cycle 後，帳本在 worker thread 投影該輪完整 `all_features`，記錄 identity、daily price、intraday price、order book、price history、financials、revenue、ownership flows、news/events、industry、cross-market 共 11 個領域。每個領域分開保存 availability、freshness、來源、證據時間、失效時間、下次更新時間與證據引用；未接來源維持 unavailable。模型與 API 可依深入狀態、特定資料缺口、新增部位資格及穩定 cursor 查詢；App 只顯示真實分母與缺項，不把有帳本列寫成全面研究完成。

隔離 fixture 以 58,056 列重現：同步 5.224 秒、200 列過濾查詢 0.007 秒、SQLite 65.871 MiB，程序峰值 RSS 351,256,576 bytes。這只證明本機投影路徑可承受目前分母且不阻塞持倉管理；真實來源批次延遲、失敗率及記憶體預算仍屬任務 08 缺口。完整契約、竄改稽核與剩餘範圍見 [逐檔研究覆蓋報告](../audits/autonomous-security-research-coverage-20260913.md)。

## 第十輪：官方市場更新 SLO 與傳輸恢復

正式研究循環在任何來源請求前保存不可事後改寫的 300 秒 SLO，要求六個市場主檔分區全數成功或由可核對的新鮮快取滿足，且嘗試失敗率為零。TPEx 大型 JSON 僅在 Content-Length、Accept-Ranges 及 ETag／Last-Modified 完整證據下以精確 Range 恢復；版本改變、區間斷裂或長度不符即拒絕。已到期歷史權證的 4,656 筆發行資料缺口留在獨立帳本，當期或未來權證仍會阻擋市場基準。

第一次冷啟動循環六分區全數成功、失敗率 0%、現行主檔完整，但 639.873 秒超過 SLO；收據保留 breach。緊接著的正常增量循環在 42.656 秒完成六個分區，獨立稽核逐一核對 checkpoint 成功狀態、cursor、6 小時 TTL 及宣告時間的新鮮度，因此任務 08 的增量更新驗收通過。同輪深查 `2426.TW` 因完成歷史不足失敗，已保留為逐檔缺口，不混入市場主檔 SLO。

完整回歸為 **3,456 passed、5 skipped、0 failed**；正式循環共 49,262 檔、1,936 檔通過新增部位商品門檻。帳戶前後均為 TWD 1,000,000，0 計畫、委託、成交與持倉；模型維持 `gpt-5.6-sol`／medium，2026-09-14 配額 0／1，未提前呼叫。程式、正式來源、隨後增量、覆蓋帳本、帳戶不變與原生 App 證據見 [SLO 驗收報告](../audits/autonomous-market-update-slo-20260914.md)。M1 仍等待 14:30 後的自然模型複查與後續真行情進出場；M7–M9 未改變。
