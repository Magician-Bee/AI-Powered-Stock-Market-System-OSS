# 自主交易系統實作與驗收目標

2026-09-12 起以 [M0–M9 完整目標](autonomous-trading-goal-20260912.zh-TW.md) 為最高主線；本文保留先前實作及驗收歷史，不能以舊完成率代替新版里程碑。初始服務、真實資料路徑與失敗收據見 [M0 基準](../audits/autonomous-goal-m0-baseline-20260912.md)。

使用者目標（2026-09-11）：最終接真實券商，由系統從全市場主動找機會、全面取證分析、決定部位與進出場時間、等待條件、下單、管理成交與持倉，再以扣成本績效改進。當前以紙上券商驗證**同一條正式交易流程**，不是另做示範策略或固定買一股。

## 執行原則

- 策略由系統研究與判斷，無須使用者提供 K 線規則。
- 全市場先用批次資料篩選，預設每輪對 20 檔從未查或最久未查的普通股深入取證，持久記錄逐檔成功與缺口；資料或決策無變化時不重複花費模型資源。
- Host 根據動作實際需要的資料、權限、帳本和回報驗證，移除錯誤分類、無關依賴與格式誤判造成的阻擋。
- 研究、估值、建立交易計畫、可執行報價、實際成交分開記錄；合理研究和等待狀態可繼續，不能冒充已成交。
- 紙上與券商介面共用交易計畫、時間／價格／事件觸發、sizing、成本、風控、委託狀態、持倉保護及對帳契約。此階段不送出真實資金委託。
- 正期望值必須有扣成本、時間順序正確、樣本外與前瞻的證據。資格狀態包含樣本、限制與失效原因，不能由模型自評分數代替。

## 工作流與交付

1. 修復已重現的分數門檻漏判、報價時間誤用、自動化 confidence／action／session 遺失及模型日預算不生效。
2. 共用策略執行規則，讓回放與下單使用一致的部位、加減碼、停損、停利與成本；建立少量具明確依據的候選策略及不可事後改選的驗證切分。
3. 持久交易計畫：股票池、候選、證據、策略版本、淨期望、風險、資金、立即／定時／條件進場、有效期、重新評估與取消條件。
4. 自主執行：冪等送單、委託／部分成交／拒單／撤改單、持倉監控、加減碼和出場；重啟後先對帳，再續接未完成動作。
5. 以一致帳本保存持倉估值、完整買賣、費稅滑價、淨值與策略版本，完成 episode／reward／檢討／重新驗證流程。
6. 一個整合 Agent 任務驗收研究到交易、失敗恢復及績效核對；小功能用合併離線測試，不逐一反覆呼叫雲端模型。

## 後續正期望值驗收

1. 為歷史股票池、權息／分割及資料首次可得時間建立可重播版本，依策略實際輸入要求相應證據。
2. 將模型、提示、工具依賴與部位政策凍結為策略版本，讓多份交易計畫可歸屬同一可驗證策略；改動後不得沿用舊績效資格。
3. 在未來行情到來前鎖定前瞻紙上觀察方案，保存進場、不交易與拒絕紀錄；依預先條件評估扣成本期望、回撤與不確定性。
4. 保存真行情及委託事件，量化延遲、價差、限價未成交與部分成交對回測的差異。
5. 將平倉成果接成策略歸因及版本化改良流程，經獨立重新驗證後才升級。
