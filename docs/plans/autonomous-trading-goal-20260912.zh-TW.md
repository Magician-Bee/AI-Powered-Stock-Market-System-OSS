# AI 全市場自主交易系統：最終目標開發計畫

**本計畫的最高優先級，是讓 AI 真正完成「自主研究市場、選擇策略與股票、決定資金及進出場條件、持續執行與管理、驗證成果，最後接上真實交易」的完整流程。**

不是增加功能數量，不是把介面做得更複雜，也不是先打造另一套通用 Agent 平台。

以下規劃以剛才檢查的 `270e59a6` 為基準，**保留既有 `AutonomousCampaign`、`TradingPlan`、`TradingPlanExecutor`、Paper OMS、Agent Runtime 與前瞻驗證架構，優先修正、接通及驗收，不重新做第二套。** 現有專案已經具備這些主要組件與組裝路徑。

---

## 一、唯一的最終目標

> **使用者授權市場、帳戶、資金及風險範圍後，AI 不需要使用者逐檔指定股票或逐次催促，自行持續研究全市場，使用相關且可取得的行情、技術、基本面、籌碼、新聞、事件、產業及跨市場資料，自主提出、驗證、比較與改進策略。**
>
> **AI 自行決定哪些股票值得交易、哪些應等待或排除、買多少、什麼時間與價格進場、等待什麼條件、持有多久，以及什麼情況下加碼、減碼、停損、停利或全部退出。**
>
> **這些判斷必須轉成持久、可執行、可追蹤的交易計畫，由同一套交易流程完成委託、成交、持倉管理、對帳與成果記錄。先用真實市場資料持續紙上交易，取得扣除成本後有價值的證據，再經明確授權逐級進入真實交易。**

這裡將你說的「找出所有會賺錢的」，轉成可以驗收的要求：

**持續尋找全市場中具有可驗證獲利優勢的機會，而不是承諾預知每檔股票的未來、每筆都賺錢，或把所有看好的股票全部買進。** 系統必須同時衡量不確定性、資金限制、交易成本與可能損失；「目前沒有值得交易的機會」也可以是有效結論。

### 四個不可偷換的定義

| 你的要求             | 本計畫採用的定義                                                                   |
| ---------------- | -------------------------------------------------------------------------- |
| **所有股市股票**       | 最終涵蓋台股、美股及其他股票市場；逐市場建立完整股票名單與覆蓋紀錄。先完成台股是交付順序，不代表把最終目標永久縮成台股。尚未接入的市場必須列為缺口。 |
| **全面分析、用盡工具能力**  | AI 能自主選擇並取得與交易假說相關的必要證據，也能補查矛盾與缺項；不能只跑兩個指標就宣稱全面分析，也不要求毫無目的地把每個工具全部執行一遍。    |
| **知道買多少、什麼時候買賣** | 有根據的資金配置、時間窗口、價格條件、失效條件與退出政策；不是只輸出一句「建議買進」。                                |
| **紙上與實盤原則相同**    | 共用研究、決策、計畫、風控、委託狀態與持倉邏輯；成交來源及券商能力由介面區分，不能假設模擬成交等同真實成交。                     |

紙上模擬與實盤確實需要分別驗證。券商官方文件也明確指出，模擬可能無法完整反映市場衝擊、延遲滑價及委託排隊位置等因素。([Alpaca US][1])

## 二、開發範圍：哪些做，哪些不做

**只有直接改善下列鏈條的任務，才可以进入主線：**

```text
市場覆蓋與資料
    ↓
AI 自主研究及策略選擇
    ↓
機會比較與全帳戶資金配置
    ↓
具體進出場交易計畫
    ↓
委託、成交與持倉管理
    ↓
持續重新評估
    ↓
對帳、成果驗證與策略改善
    ↓
受控真實交易
```

不以新增 UI 主題、重寫通用 Agent、多做聊天功能、擴充無關 Computer Use、湊工具數量、同時接滿所有券商、建立另一套排程平台或訓練自己的大模型，作為這條主線的前置工作。

**但會影響資金正確性、憑證安全、行情真實性、重複下單、停損退出與中斷恢復的工作，不屬於無關任務，必須保留。**

### AI 與 Host 的責任

**AI 負責投資判斷：**研究什麼、使用哪些工具、形成什麼假說、採用什麼策略、交易哪些股票、配置多少資金、什麼條件進出場，以及何時需要重新研究。

**Host 負責可靠執行與不可越過的邊界：**保存狀態、驗證資料與權限、執行計算、檢查使用者核准的風險限制、處理排程與委託、核對成交及帳本。

**Host 不得用固定策略代替 AI 的投資判斷；AI 也不得為了通過驗收而自行取消風控、改寫成交或擴大資金授權。**

使用者可以一次授權持續交易的範圍，範圍內不需要每一筆都重新詢問；實盤啟用、增加資金上限、放寬風險或新增未授權交易能力，則仍需明確批准。

# 三、總體里程碑規劃表

以下編號是本次目標計畫的里程碑，不以舊功能清單完成率代替。

| 里程碑                | 直接目標              | 交付後必須出現的實際能力                   | 未達成時不得宣稱             |
| ------------------ | ----------------- | ------------------------------ | -------------------- |
| **M0：固定主線與實際基準**   | 確認目前真正運行的版本、帳戶與流程 | 能對照程式、執行版本、交易資料庫及測試證據，指出實際斷點   | 「程式存在，所以已完成」         |
| **M1：可靠紙上交易最小閉環**  | 先讓既有流程完整且可靠地運作    | 真模型取得真資料，自主提案，透過紙上委託完成持倉與出場對帳  | 「固定假行情測試通過＝AI 已自主交易」 |
| **M2：全市場資料與研究覆蓋**  | 不再只輪替少量股票而錯過市場    | 全市場持續更新，AI 可對任意候選按需深入研究，缺口清楚可見 | 「掃描過＝全面深入分析過」        |
| **M3：真正自主研究與策略形成** | 不限固定策略，不只產生報告     | AI 能選工具、補資料、形成假說、比較策略及判斷不交易    | 「工具有登錄＝研究已做完」        |
| **M4：資金與進出場決策**    | 回答買多少、何時買、多久後賣    | 每個候選轉成與全帳戶風險一致的具體交易計畫          | 「模型隨口提出比例＝合理部位」      |
| **M5：完整委託與持倉管理**   | 不只會送單，還能處理交易後續    | 部分成交、撤改單、跳空、停損、到期與中斷都能持續處理     | 「已送出賣單＝已經退出」         |
| **M6：持續自主運作**      | 不需使用者每天重新下指令      | 盤前、盤中、盤後及重大事件能適當喚醒 AI；UI 關閉仍運作 | 「有排程＝能長期自主交易」        |
| **M7：獲利價值驗證與改善**   | 證明決策在新資料上有價值      | 真實前瞻紀錄、成本後成果、風險與基準比較、版本化改善     | 「幾筆獲利＝已證明有效」         |
| **M8：真實券商逐級接通**    | 把同一條鏈移到真實交易       | 正式登入、行情、對帳、測試環境及受限實盤逐級驗收       | 「切換設定＝實盤完成」          |
| **M9：跨市場完整擴展**     | 達到其他股票市場，而非停在單一市場 | 各市場以相同契約納入資料、研究、配置、執行及驗證       | 「台股完成＝全球完成」          |

**執行原則：先取得 M1 的可靠閉環，再逐步扩大研究範圍與決策能力。M7 的資料收集應儘早開始，不要等所有功能開發完才開始記錄。**

# 四、詳細開發規劃表

## M0－M1：先證明這條交易流程真的接通

目前專案的閉環驗證程式使用固定測試行情，並明確不呼叫真實模型。它適合驗證程式路徑，但不能替代真模型、真市場資料的自主交易驗收。

| 任務                     | 必須完成的工作                                             | 驗收條件                                                                  |
| ---------------------- | --------------------------------------------------- | --------------------------------------------------------------------- |
| **01．建立精確執行基準**        | 核對實際服務版本、資料庫、帳戶、模型設定、啟用狀態與主要交易路徑；保留現有資料，不重設帳戶來掩蓋問題。 | 每份測試與交易證據都能定位到提交版本、模型、設定及帳戶；不能拿舊版本成功紀錄替最新版本背書。                        |
| **02．建立任務到目標的對照**      | 每個開發任務註明它改善哪個里程碑、修正什麼斷點、如何驗收。已有實作先測試及補接線，不直接重寫。     | 找不到與本計畫直接關係的任務，不進入主線；完成判定必須指向執行證據。                                    |
| **03．優先修正阻斷交易生命週期的問題** | 優先處理提案無法落地、帳戶讀錯、成交狀態不明、出場單長期等待、重啟後重複送單等問題。          | 故障情境下仍能識別真實狀態；不製造假成交、不遺失既有風險、不因重試增加未知部位。                              |
| **04．完成真模型紙上閉環**       | 使用實際模型和即時取得的市場資料，自主研究、提案、等待條件、紙上買進、管理、退出及對帳。        | 形成完整的「研究→決策→計畫→委託→成交→退出→成果」證據鏈。沒有符合條件時可不交易，但必須另完成交易路徑驗收，不能以長期零交易宣稱完成。 |

**M1 只證明流程能運作，不宣稱策略已賺錢，也不要求為了測試而强迫 AI 隨便買一筆。**

## M2：全市場資料、覆蓋與深入研究能力

目前提案建立器要求標的出現在該輪保存的研究結果中，而深入研究每輪有數量上限。因此，除了擴大資料吞吐量，也必須解除「AI 想研究其他股票，卻被當輪名單限制」的問題，同時保留來源核驗。

| 任務                   | 必須完成的工作                                                | 驗收條件                                                    |
| -------------------- | ------------------------------------------------------ | ------------------------------------------------------- |
| **05．建立完整市場股票名單**    | 從正式來源更新各市場證券名單，處理上市、下市、更名、轉板、代碼重用及商品類別；交易資格與研究範圍分開。    | 名單不是使用者自選股，也不是成交量前幾名；每個排除項目都有原因，未覆蓋市場不得從總目標中消失。         |
| **06．接齊決策所需資料**      | 整合日線、盤中行情、成交量、相關買賣報價、財務、營收、籌碼、新聞事件、產業及跨市場資料；按市場取得相應資料。 | 每個資料領域都有實際讀取路徑、來源、時間、可用性與缺項紀錄，不以空欄位或套件存在當作完成。           |
| **07．統一資料真實性與時間規則**  | 保存來源時間、接收時間、修訂版本、股票身分及公司行動；區分可供研究與可供執行的行情。             | 過時資料不得當即時價格；回測不得讀到當時尚未公開的資訊；資料衝突可被追蹤與處理。                |
| **08．擴大全市場更新吞吐量**    | 批次取得、增量更新、共享快取、受控並行與來源限流；歷史補資料不得阻塞持倉保護。                | 在事先設定的更新時效內完成全市場基礎更新；實測吞吐量、延遲與失敗率，而非只把 `deep_limit` 改大。 |
| **09．讓 AI 按需深入任意候選** | AI 能指定需要深入的股票，自動補齊其歷史及其他證據，再產生可驗證的研究版本；輪替名單只作補充覆蓋機制。   | AI 不受最新一輪少數股票結果鎖住；任意合範圍標的都能進入「補資料→研究→提案」，缺資料則說明原因。      |
| **10．建立逐檔覆蓋帳本**      | 記錄每檔股票各資料面向的最新狀態、最後深入研究時間、失效時間及下次更新需求。                 | 「曾經研究」「目前資料仍有效」「尚未深入」「來源缺失」清楚區分；每檔必有狀態，但不能把有狀態說成資料齊全。   |

歷史資料的版本控制不是額外裝飾。Qlib 官方說明指出，直接使用最新修訂財務資料進行過去時點的回測會產生資料洩漏，必須使用當時可得版本。([Qlib Documentation][2])

**這個階段的重點不是讓大模型逐字閱讀所有股票的全部歷史，而是讓全市場持續受監測，並讓 AI 能把深入研究資源投入真正需要判斷的地方，不漏掉長期未被关注的股票。**

## M3：AI 自主研究、形成策略與挑選機會

| 任務                 | 必須完成的工作                                                                              | 驗收條件                                               |
| ------------------ | ------------------------------------------------------------------------------------ | -------------------------------------------------- |
| **11．接通實際可用的研究工具** | 建立與交易直接相關的工具能力表，核對實際輸入、輸出、權限、成本、限制與失敗行為。已有 Qlib、FinRL、TradingAgents 等能力只在能提供有效研究時使用。 | Agent 能在正式執行流程呼叫並取得結果；「已安裝」「已登錄」不算接通。              |
| **12．建立動態研究流程**    | AI 自行決定先研究哪些問題、需要哪些證據、矛盾要如何查證、何時資料已足夠或應停止研究。                                         | 不把每個任務寫死成相同工具順序；每輪有研究問題、已取得證據、未解問題與停止理由。           |
| **13．支援自主策略假說**    | AI 可以形成趨勢、事件、基本面、產業輪動或混合策略，也可在隔離研究環境中產生策略程式、訓練或比較模型。                                 | 不限既有兩個固定策略；新策略有明確規則、版本及可重現測試，不能直接改寫正在交易的執行程式。      |
| **14．建立機會比較與反證**   | 對候選比較預期收益、可能損失、成本、流動性、持有時間、資料可信度與反方情境。                                               | 不能只用模型自評信心排名；能說明為何選這檔、為何不選其他候選，以及什麼資訊會推翻判斷。        |
| **15．建立決策證據契約**    | 每份決策列出必要資料與附加資料、取得狀態、來源時間、矛盾及缺項影響。                                                   | 不得把僅有 K 線的決策稱為已完成所有面向分析；缺少某策略的必要證據時，不得把該策略當作已驗證機會。 |

**不要把「策略尚未證明有優勢」和「連紙上試驗都不准做」混為一談。**

允許 AI 在已授權的紙上風險預算內提出新假說並收集證據，但必須清楚標成試驗；不能把試驗權限當成獲利資格。你目前的自主交易指南已經有這個區分，應保留。

## M4：決定買多少、何時買，以及多久後賣

這是整個計畫的核心，不能只做到選股。

| 任務                 | 必須完成的工作                                                      | 驗收條件                                         |
| ------------------ | ------------------------------------------------------------ | -------------------------------------------- |
| **16．全帳戶資金配置**     | AI 比較所有候選、既有持倉、未成交掛單與保留現金，決定各標的配置；使用可靠計算工具評估相關性、產業集中、波動與流動性。 | 配置是整個帳戶的共同決策，不是每檔各自拿一筆假想資金；多個計畫同時成立也不能超配。    |
| **17．把配置轉成實際股數**   | 依可用資金、預計進場價格、成本、交易單位及帳戶限制計算股數；需拆單時明確記錄子委託。                   | 原始配置、實際股數、成本預留、剩餘現金與縮減原因可核對；不能默默改成系統最大部位。    |
| **18．比較不同進場方式**    | AI 比較立即進場、指定日期時間、突破、回檔、事件後確認、分批或放棄交易。                        | 每個候選有進場方法及理由；無法支持精確到分鐘的判斷時，使用時間窗口與條件，不製造假精準。 |
| **19．形成可執行交易計畫**   | 保存最早進場時間、價格條件、有效期限、最大追價範圍、證據失效條件與重新研究需求。                     | 不只是文字建議；程式能判斷現在是等待、觸發、過期、失效還是需要重新評估。         |
| **20．形成完整持倉與退出政策** | AI 決定停損、停利、最長持有時間、事件失效、加減碼及提前退出條件；調整必須留版本。                   | 每個持倉都有管理政策；不得只有買進理由而沒有退出規則，也不得藉放寬停損突破授權風險。   |

### 每一筆 AI 交易計畫至少要回答這些問題

| 問題            | 必須產生的內容                  |
| ------------- | ------------------------ |
| 為什麼選它？        | 交易假說、證據、反方風險及相對其他候選的優勢。  |
| 買多少？          | 股數、資金占比、估計成本、與其他持倉合計的風險。 |
| 現在買還是等待？      | 立即、日期時間、價格條件、事件條件或不交易。   |
| 等多久？          | 最早時間、有效窗口、到期後取消還是重新研究。   |
| 價格不一樣了怎麼辦？    | 可接受價格範圍、追價限制、跳空後是否重新評估。  |
| 買了之後怎麼辦？      | 持有理由、監控事項、加減碼條件、重新評估時點。  |
| 什麼時候賣？        | 停損、停利、最長持有期限、事件或策略失效條件。  |
| 沒成交或系統出問題怎麼辦？ | 撤改單政策、對帳流程、保護措施及告警。      |

現有 `TradingPlan` 已經有股數、資金、時間、觸發價及持有期限等欄位，所以應在既有結構上補完整決策契約與執行語義，而不是另開一套文字計畫系統。

## M5：委託、成交、停損與持倉生命週期

目前出場路徑存在「送出限價單後，委託仍開啟就繼續等待成交」的分支。這使得**停損觸發後的未成交處理**成為應優先驗證及補完的項目。

| 任務                   | 必須完成的工作                                        | 驗收條件                                                  |
| -------------------- | ---------------------------------------------- | ----------------------------------------------------- |
| **21．統一紙上與實盤執行契約**   | 共用計畫、意圖、股數、風控、狀態與成果接口；券商介面如實暴露支援的委託能力及差異。      | 更換券商不重寫策略；不支援的能力明確拒絕或由已核准的等效政策處理，不能偷偷改變交易意思。          |
| **22．送單前重新確認**       | 條件觸發時重新核對行情、交易時段、帳戶、現金、掛單預占、成本、交易限制及資料是否已失效。   | 幾天前建立的計畫不能不經檢查直接照單全收；價格或帳戶變化後不會超配。                    |
| **23．完整委託狀態管理**      | 處理接受、拒絕、部分成交、撤單、改單、過期與回報不明；先保存意圖，結果不明先查證。      | 重啟、重試、重複回報都不會重複增加委託或成交；不能把缺少回報解讀成可以重新送一筆。             |
| **24．補完未成交出場政策**     | 為停損、停利與到期退出定義等待、撤單確認、重掛、價格界線及升級告警；按券商能力使用相應保護。 | 95 元停損單未成交、價格續跌時，不能無限顯示「正在停損」；必須按政策處理，仍無法退出時明確顯示剩餘風險。 |
| **25．處理實際剩餘持倉與公司行動** | 依真實已成交股數管理退出；處理部分成交、股利、拆併股、交易單位、可用交割資金與計畫必要調整。 | 不超賣、不遺失剩餘股數、不因公司行動產生錯誤停損；帳戶及策略成果可核對。                  |

### 必須通過的故障測試

至少涵蓋：進場後立即反向、跳空越過停損、部分成交後撤單、出場單不成交、行情中斷、券商回報遺失、重複回報、送單前後程式崩潰、跨日重啟，以及使用者停止新進場。

測試要求不是「所有情況都能成功成交」，而是：

> **任何情況都知道已經發生什麼、還持有多少風險、接下來允許做什麼；不確定時不猜、不重複擴大部位，也不放棄既有持倉管理。**

## M6：持續自主運作，不需要每天重新叫它

| 任務                     | 必須完成的工作                                                  | 驗收條件                                          |
| ---------------------- | -------------------------------------------------------- | --------------------------------------------- |
| **26．後端持續任務與恢復**       | 任務、等待條件、委託、持倉、模型複查與重試進度全部持久化；測試實際行程終止及重新啟動。              | 關閉 UI 不停止交易管理；服務恢復後接續原狀態，不建立第二個重複執行者。         |
| **27．建立事件驅動的 AI 複查**   | 盤前、盤中、盤後、重大新聞、候選條件改變、持倉假說失效及風險異常，可喚醒相應研究。                | 不再只有固定每天一次模型任務；也不因每個價格跳動都重跑完整模型，事件能去重、合併與排序。  |
| **28．研究預算與風險管理分離**     | AI 在核准的模型、資料及算力預算內自行分配研究資源；預算不足時停止非必要新研究，但保留確定性的委託與持倉保護。 | 不靠無限工具呼叫取得自主性；模型離線或額度耗盡時，不會連停損與對帳也一起停掉。       |
| **29．統一實際模型設定與最小操作畫面** | 自主任務使用明確保存的模型及能力設定；既有畫面呈現研究覆蓋、候選、計畫、掛單、持倉、風險與績效。         | 使用者能分辨「市場沒有機會」與「系統故障所以沒交易」；切換模型不暗中改變已凍結的驗證政策。 |

目前自動複查路徑指定 Codex，預設每日任務及步驟有上限。要改善的是**這條自主交易路徑的設定一致性、喚醒條件及預算設計**，不是順便把所有模型供應商全部接一遍。

等待價格與時間由程式執行；出現需要新判斷的資訊才交給 AI。**這不是削弱 AI，而是避免把可靠執行也變成每次重新猜測。**

## M7：驗證它是否真的有價值，並持續改善

| 任務                   | 必須完成的工作                                                       | 驗收條件                                                 |
| -------------------- | ------------------------------------------------------------- | ---------------------------------------------------- |
| **30．歷史研究與前瞻驗證分開**   | 歷史策略以時間切分評估，保留獨立測試資料；真模型紙上決策在結果發生前記錄。不能排除後見資訊的歷史 LLM 回放，只作探索。 | 不用未來資訊、不反覆挑測試區間贏家；固定測試行情不得混入真市場績效。                   |
| **31．凍結驗證政策與隔離開發環境** | 保存模型、提示、工具、決策相關程式、成本及風險設定；開發版與驗證版分離。                          | 修其他功能不應無理由破壞驗證；真正影響政策的變更必須留下版本與偏離紀錄，不能把不同版本績效偷偷接在一起。 |
| **32．建立全帳戶淨成果帳本**    | 保存現金、持倉、掛單、股利、每日淨值、已實現及未實現損益；另外計入 AI、資料及運行成本。                 | 能區分「交易扣成本後賺錢」與「整個系統扣營運成本後賺錢」；滑價已反映在成交價時不得重複扣除。       |
| **33．建立事前登記的資格判定**   | 事前決定觀察期、樣本要求、風險限制、比較基準、統計方法與成本壓力情境；考量同時嘗試多個策略的影響。             | 正報酬、少量平倉或高勝率都不能單獨取得資格；必須達到原先登記的經濟及風險條件，證據不足則繼續觀察。    |
| **34．讓改善經過驗證再採用**    | AI 從失敗與獲利紀錄提出具體改善假說，先在研究或影子環境比較，再按授權政策部署。                     | 不把「寫了反省」算成已學會；能指出改了什麼、新資料上改善了什麼、是否增加風險或成本。           |

回測過度擬合研究指出，嘗試多個策略配置後挑選漂亮結果，可能造成對樣本外表現的錯判。因此，「AI 想很多策略」必須與試驗登錄、獨立資料及前瞻驗證一起設計。([SSRN][3])

現有方案包含至少 120 次每日觀察與 30 筆平倉等要求。**這些是既有驗證設定，不是達到數量就自動合格，也不能為了湊筆數强迫交易；已登記方案不得事後放寬條件來讓結果過關。**

另外要明確區分：

**凍結政策，不等於凍結每一筆決策。** 同一個已凍結的 AI 決策政策，仍應能因新行情或新聞而改變選股、資金配置及進出場；真正需要重新建立驗證版本的是決策方法、模型、工具、風險或成本規則的變更。

## M8－M9：真實券商與跨市場擴展

| -------------------- | ------------------------------------------------- | ---------------------------------------------- |

| **37．通過測試環境並啟用受限實盤** | 沿用既有逐級升級規則，通過所需驗收後，由使用者批准帳戶、市場、資金與風險範圍。           | 真實交易只能由同一受控執行入口發出；未取得證據或授權的等級保持關閉，不因紙上成功自動開實盤。 |
| **38．量測紙上與實盤差異**     | 比較實際成交率、部分成交、延遲、滑價、成本及退出品質，回饋到模擬與研究。              | 不把紙上績效直接當實盤預測；實盤偏離原假設時能降級、停止新進場或重新驗證。          |
| **39．建立各市場專屬規則**     | 逐市場接上股票名單、資料來源、時區、夏令時間、交易日曆、幣別、交易單位、公司行動、交割及帳戶限制。 | 相同股票代碼不混淆、不同市場現金不重複使用、不同時區不提前或延後錯誤送單。          |
| **40．整合全球資金配置與覆蓋**   | AI 跨市場比較機會、匯率與共同曝險，依同一帳戶體系配置資金；所有目標市場保留覆蓋與驗收狀態。   | 台股、美股及其他市場逐一通過同等標準；未接入或不可交易項目如實列明，不能宣稱已完成全球覆蓋。 |

目前正式券商 SDK、登入生命週期、對帳及行情恢復仍有未完成驗收項目，因此實盤階段不能被簡化成「換一個 Broker 參數」。

# 五、具體開發順序：避免又變成「想到什麼就做什麼」

## 第一輪：先讓現有流水線可靠

**執行 01－04，並提前處理 23－24 的重大缺陷。**

先完成一條真模型、真資料、紙上帳本的生命週期，尤其確認「買了之後能可靠管理和退出」。

這一輪允許使用有限標的完成工程驗收，但報告必須標為有限範圍，不能提前宣稱全市場完成。

## 第二輪：讓 AI 真正有全市場選擇權

**執行 05－15。**

重點是全市場資料更新、研究時效、按需補證據、解除當輪候選限制，以及動態研究與策略形成。

此時不能只增加每輪股票數，卻讓模型仍只能從固定名單或固定策略選擇。

## 第三輪：完成投資決策及交易管理

**執行 16－25。**

把「看好股票」變成真正的全帳戶配置、進場條件、等待期限、持倉政策與未成交處理。

## 第四輪：完成持續自主運作

**執行 26－29。**

把盤前、盤中、盤後、重大事件、故障與恢復接在同一持久任務上，不再依賴使用者每天重新叫它。

## 第五輪：持續驗證與改善

**01－04 通過後就開始收集 30－34 所需紀錄；正式資格從已凍結且符合契約的版本開始計算。**

不要等所有功能完工才開始觀察，也不能把早期不相容的試驗資料全部混入正式資格。

## 第六輪：真實交易與其他市場

**通過相應資格與授權後，執行 35－40。**

券商唯讀接線與其他市場資料準備可以提前並行；**實盤啟用不能因此提前，其他市場也不能只接行情就算交易能力完成。**

# 六、最終交付時，使用者應該實際看到什麼？

不是一段「已完成全市場分析，建議關注某股票」的文字，而是類似以下的持續狀態。以下均為功能示例，不是交易建議。

| 對象      | AI 決策與系統行為                              |
| ------- | --------------------------------------- |
| 股票 A    | 證據支持進場，配置已考量既有持倉與成本；符合目前價格窗口，建立並執行買進計畫。 |
| 股票 B    | 尚未符合條件，指定日期之後若突破某價且流動性合格才進場；未觸發則保留現金。   |
| 股票 C    | 等待已確認日期的財報或事件；事件發生後重新研究，不能現在假設結果。       |
| 股票 D    | 單檔看好，但與目前持倉高度重疊，因此減少配置或不買。              |
| 既有持倉 E  | 原假說仍成立，繼續持有；某事件或價格條件發生時重新評估。            |
| 既有持倉 F  | 假說失效，提出退出；系統追蹤實際成交及剩餘股數，而不是送單後就停止管理。    |
| 整體帳戶    | 顯示現金、掛單預占、持倉曝險、淨值、交易與營運成本、績效資格及下一次必要行動。 |
| 資料或模型異常 | 明確顯示技術阻擋，停止不可靠的新進場；既有委託對帳及可執行的保護流程繼續運作。 |

**使用者的日常角色應是查看結果、調整授權邊界及處理必要異常，而不是每天指定股票、告訴 AI 下一步，或手動追問為什麼沒有賣。**

# 七、交給開發 Agent 的最高優先級指令

下面這段可與上方規劃表一起交給開發 Agent：

> **本專案唯一主線，是完成全市場自主股票交易：由 AI 自主研究、選擇工具與策略、選股、配置資金、決定進出場時間與條件，透過同一套受控執行流程完成紙上交易、持倉管理、成果驗證，最後逐級接通真實券商與其他股票市場。**
>
> 保留並延伸既有 Agent Runtime、AutonomousCampaign、TradingPlan、TradingPlanExecutor、OMS、資料與驗證架構。先驗證現有路徑並修正斷點，不另建第二套系統。
>
> 每個任務必須對應本計畫的里程碑、實際斷點及驗收證據。不得用 UI、檔案、類別、API、工具登錄或測試數量代替完整能力。
>
> 不得把全市場掃描當成全市場深入研究；不得把固定測試行情當成真市場績效；不得把提案當委託、委託當成交、送出賣單當完成退出，也不得把少量獲利當成策略已被證明。
>
> AI 自主決定投資判斷；Host 僅承擔必要的可靠執行、證據核驗及使用者核准的硬性邊界。不得用固定選股或固定策略代替 AI，也不得為通過測試而放寬風控、偽造資料或自行開啟實盤。
>
> 研究、策略與交易計畫可以在既定授權內自主調整；最終目標、授權範圍、實盤資金、硬性風險及驗收標準，不得被 Agent 自行改寫。
>
> 優先交付真模型、真行情、可追溯決策及可靠出場的紙上閉環，再擴大全市場研究、配置能力與跨市場交易。遇到阻擋時，記錄具體缺項、影響及可繼續的工作；不得轉去做無關功能，也不得跳過必要的安全與資金驗證。
>
> 每次回報只回答：本次推進哪個目標、實際改了什麼、取得哪些證據、還有哪些阻擋，以及下一個直接支持最終目標的任務。

**這份計畫的終點不是「做出很多看起來完整的功能」，而是：你給定授權與風險邊界後，系統能持續自己找機會、自己作出具體投資決策、可靠完成買賣與持倉管理，並用不可混淆的實際結果證明它是否值得投入真實資金。**
